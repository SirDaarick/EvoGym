# P2.2 — Member Reload DTO Specification (`MemberReloadDTO`)

Technical specification and versionable contract for member reloadable read operations, resolving frontend gap FE05 while enforcing tenancy rules (D-001), role-based projection (D-012), and monetary standards (D-003).

---

## Quick Summary

| Topic | Decision / Specification |
|---|---|
| **Contract Name & Version** | `MemberReloadV1DTO` (`GET /api/v1/members/{id}/reload`) |
| **Primary Target** | Replaces ephemeral checkout responses with durable, reloadable member state containing stable UUIDs for periods, class samples, itemized debts, and check-in visits. |
| **Role Projections** | **Receptionist:** Operational demographic profile, valid membership dates, single-entry sample availability, branch check-in history, and a boolean `has_pending_balance` warning flag.<br>**Admin:** Full operational profile plus itemized debts (`order_id`, `initial_outstanding_minor`, `remaining_balance_minor`), financial summaries, and administrative audit trails. |
| **Multi-Branch Isolation (D-001)** | Member profiles are organization-shared. Entitlements with `branch_id = null` are multi-branch. Check-in visit logs and itemized debt repayments are strictly branch-isolated. |
| **Data Standards** | Currency strictly `MXN` (D-003). All monetary values in 64-bit integer minor centavos (`bigint`). Timestamps in UTC ISO 8601 (`YYYY-MM-DDTHH:mm:ss.sssZ`, D-004). Collections default to empty list `[]`, never `null`. |
| **P1 Dependency Gate** | Principal extraction, bearer token transport, and request ID headers are designated `PENDING P1`. |

    email: str | None = Field(default=None, max_length=320)
    birth_date: date | None = Field(default=None, description="Personal date of birth; age derived on display")
    joined_on: date = Field(..., description="Date joined gym")
    status: Literal["active", "inactive", "expired", "suspended", "pending"] = Field(...)
    photo_url: str | None = Field(default=None, max_length=512)
    emergency_contact_name: str | None = Field(default=None, max_length=160)
    emergency_contact_phone: str | None = Field(default=None, max_length=32)


class MemberPeriodReadDTO(BaseModel):
    """Stable membership period entitlement with validity interval."""
    model_config = ConfigDict(from_attributes=True, extra="forbid")

    id: UUID = Field(..., description="Stable membership period UUID")
    order_item_id: UUID = Field(..., description="Originating order line item UUID")
    plan_version_id: UUID = Field(..., description="Immutable published plan version UUID")

        default=None,

    )
    is_current: bool = Field(..., description="True if today falls within [starts_on, ends_on) in branch timezone")
    access_status: Literal["eligible", "expired", "restricted_unpaid", "restricted_admin", "branch_restricted"] = Field(
        ..., description="Access status derived by evaluate_membership_access"
    )


class ClassSampleReadDTO(BaseModel):
    """Single-entry paid class sample entitlement per D-019."""
    model_config = ConfigDict(from_attributes=True, extra="forbid")

    id: UUID = Field(..., description="Stable sample entitlement UUID")
    order_item_id: UUID = Field(..., description="Originating order line item UUID")
    plan_version_id: UUID = Field(..., description="Plan version UUID")
    plan_name: str = Field(..., min_length=1, max_length=120)
    is_consumed: bool = Field(..., description="True if check-in has already been recorded")
    consumed_at: datetime | None = Field(default=None, description="UTC ISO instant when consumed")
    consumed_visit_id: UUID | None = Field(default=None, description="Attendance visit UUID where consumed")


class MemberDebtItemDTO(BaseModel):
    """Itemized outstanding debt originating from partial cash payments (Admin only per D-012/D-013)."""
    model_config = ConfigDict(from_attributes=True, extra="forbid")

    debt_id: UUID = Field(..., description="Stable debt record UUID")
    order_id: UUID = Field(..., description="Target order UUID required for repayments")
    branch_id: UUID = Field(..., description="Branch where order was created")
    currency: Literal["MXN"] = Field(default="MXN", description="Currency per D-003")
    initial_outstanding_minor: int = Field(..., gt=0, description="Initial unpaid centavos at sale")
    remaining_balance_minor: int = Field(..., ge=0, description="Current unpaid centavos after repayments")
    created_at: datetime = Field(..., description="UTC ISO creation instant")


class MemberFinancialSummaryDTO(BaseModel):
    """Financial status projection partitioned by role visibility (D-012)."""
    model_config = ConfigDict(from_attributes=True, extra="forbid")

    has_pending_balance: bool = Field(..., description="Boolean flag visible to all roles per D-013")

    credit_balance_minor: int = Field(default=0, ge=0, description="Available advance credit in centavos")
    total_pending_balance_minor: int | None = Field(
        default=None, ge=0, description="Sum of unpaid debts in centavos; None for Receptionist"

    currency: Literal["MXN"] = Field(default="MXN")
    debts: list[MemberDebtItemDTO] = Field(

    model_config = ConfigDict(from_attributes=True, extra="forbid")

    id: UUID = Field(..., description="Check-in event UUID")
    visit_id: UUID = Field(..., description="Durable visit record UUID")
    branch_id: UUID = Field(..., description="Branch where check-in occurred")

## 2. Role-Based Projection Matrix (Decision D-012)

The server enforces strict serialization filtering before transmitting bytes over the wire. Receptionists never receive administrative financial arrays, preventing data leakage at the transport layer.

| Field / Object | Receptionist Projection | Admin Projection | Member Self-Service (Future) |
|---|---|---|---|
| `profile.*` | ✅ Full operational profile | ✅ Full operational profile | ✅ Own profile only |
| `profile.emergency_contact_*`| ✅ Visible for safety | ✅ Visible | ✅ Editable |
| `active_periods[].id` | ✅ Stable UUID for check-in | ✅ Stable UUID | ✅ Visible |
| `active_periods[].access_status` | ✅ Visible | ✅ Visible | ✅ Visible |
| `class_samples[].id` | ✅ Stable UUID for check-in | ✅ Stable UUID | ✅ Visible |
| `financial.has_pending_balance` | ✅ Boolean flag | ✅ Boolean flag | ✅ Boolean flag |
| `financial.total_pending_balance_minor` | ❌ `null` (server omitted) | ✅ Total centavos | ✅ Total centavos |
| `financial.debts[]` | ❌ `[]` (empty list) | ✅ Full itemized order list | ❌ `[]` (summary only) |
| `recent_visits[]` | ✅ Current branch visits only | ✅ Current branch visits only | ✅ All personal visits |

## 3. Scoping and Tenancy Rules (Decision D-001)

1. **Cross-Branch Profile Lookup (Permitted):**
   - An authorized receptionist at Branch B can query `GET /api/v1/members/{member_id}/reload`.
   - The member's core profile (`profile`) and any multi-branch entitlements (`active_periods` where `branch_id IS NULL`) are fully returned.
2. **Cross-Branch Transaction Isolation (Denied):**
   - Branch B's response **excludes** attendance visits (`recent_visits`) and itemized debt repayments that occurred at Branch A.
   - If an entitlement is explicitly bound to Branch A (`branch_id = 'uuid-branch-A'`), Branch B's projection sets `access_status: "branch_restricted"`, signaling to the front desk that the plan is active but invalid at this physical location.
3. **Cross-Organization Boundary (Hard Denial):**
   - If `member.organization_id != actor.organization_id`, the endpoint immediately returns HTTP 404 (Not Found) to avoid leaking the existence of members in other tenants.

## 4. Pagination, Ordering, and Null Semantics

| Rule | Contract Specification | Rationale |
|---|---|---|
| **Empty Collections** | Return `[]` (empty array), never `null`. | Prevents frontend `TypeError: cannot read property of null` and simplifies client-side state mapping. |
| **Missing Member** | HTTP 404 with structured error `{ "code": "MEMBER_NOT_FOUND", "message": "..." }`. | Explicit resource absence. |
| **Nullable Demographics** | `preferred_name`, `email`, `birth_date`, `photo_url`, `emergency_contact_*` allow `null`. | Respects optional personal data collection rules. |
| **History Bounding** | `recent_visits` default limit: 20 records. Maximum limit: 50 records. Ordered `occurred_at DESC`. | Enforces bounded queries on the database and prevents memory bloat on active member profiles. |
| **Timestamp Semantics** | Strictly UTC formatted in ISO 8601: `YYYY-MM-DDTHH:mm:ss.sssZ`. | Eliminates ambiguity across client timezones (D-004). |
| **Monetary Minor Units** | Strictly 64-bit integer centavos (`bigint`). | Eliminates floating-point rounding errors (D-003). |

## 5. Error Handling and Domain Codes

All errors conform to the standardized error envelope (`PENDING P1`):

```json
{
  "code": "ERROR_DOMAIN_CODE",
  "message": "Human-readable safe explanation without sensitive internal data.",
  "request_id": "00000000-0000-7000-8000-000000000001"
}
```

| HTTP Status | Domain Code | Condition / Trigger | Safe Client Handling |
|---|---|---|---|
| **401 Unauthorized** | `AUTHENTICATION_REQUIRED` | Missing, expired, or revoked bearer token. | Clear operational session storage; redirect to PIN login screen. |
| **403 Forbidden** | `INSUFFICIENT_ROLE_PERMISSION` | Actor lacks member read grant or branch assignment. | Display access denied message; do not disclose data. |
| **403 Forbidden** | `BRANCH_SCOPE_VIOLATION` | Actor attempted an action outside their assigned branch context. | Safe refusal; keep current branch view. |
| **404 Not Found** | `MEMBER_NOT_FOUND` | Member ID does not exist or belongs to another organization (D-001). | Display "Socio no encontrado"; avoid confirming existence across tenants. |
| **422 Unprocessable** | `MALFORMED_IDENTIFIER` | Member ID is not a valid UUID format. | Inform user of invalid lookup format. |

## 6. Comprehensive Acceptance Test Matrix

This matrix operationalizes the 11 acceptance and failure points specified in `P2-member-read-contracts.md`:

| # | Acceptance Point / Test Case | Test Scenario & Input Conditions | Expected Contract Outcome |
|---|---|---|---|
| **T01** | Missing / Invalid Token | Request without `Authorization` header or with expired token. | Safe HTTP 401; empty payload; no member data or DB queries leaked. |
| **T02** | D-012 Receptionist Projection | Authenticated receptionist requests member with outstanding debts. | HTTP 200; `financial.has_pending_balance` is `true`; `total_pending_balance_minor` is `null`; `financial.debts` is `[]`. |
| **T03** | D-012 Admin Full Projection | Authenticated admin requests member with outstanding debts. | HTTP 200; `financial.total_pending_balance_minor` matches exact sum of centavos; `financial.debts` contains itemized `order_id`s. |
| **T04** | D-001 Cross-Organization Isolation | Actor from Org A requests member belonging to Org B. | Safe HTTP 404; zero data returned; existence in other org is completely concealed. |
| **T05** | D-001 Branch-Scoped Entitlement | Member with Branch A entitlement viewed by receptionist at Branch B. | HTTP 200; entitlement returned with `access_status = "branch_restricted"`; local check-in disabled. |
| **T06** | D-001 Multi-Branch Entitlement | Member with `branch_id = null` entitlement viewed at Branch B. | HTTP 200; entitlement returned with `access_status = "eligible"`; local check-in allowed. |
| **T07** | Hard Browser Reload (FE05) | Page reloads after sale completion; query `/members/{id}/reload`. | HTTP 200; returns durable `period_id` and `plan_name`; zero dependence on previous `CashMembershipSaleDTO`. |
| **T08** | Single-Entry Sample State (FE08) | Member purchased class sample; query reload contract. | HTTP 200; `class_samples` contains valid `id`; shows `is_consumed: false` before visit, `is_consumed: true` after visit. |
| **T09** | Empty Collections & Nulls | New member with no purchase history or visits. | HTTP 200; `active_periods: []`, `class_samples: []`, `recent_visits: []`, `preferred_name: null`. No crashes. |
| **T10** | Bounded History Ordering | Member with >100 historical check-in visits. | HTTP 200; `recent_visits` returns exactly 20 records (or requested page limit <= 50), strictly ordered `occurred_at DESC`. |
| **T11** | Read / Mutation Independence | Operator obtains valid `period_id` via reload contract. | Read action grants zero mutation permissions. Attempting check-in or repayment still revalidates shift, branch, and role on write. |
