# P1.5 — Local observability contract

This contract records repository behavior and bounded local evidence. It is not a production-readiness claim, hosted-CI result, or approval of operational policy.

## Request correlation and metrics

`api/app/observability/request_id.py` assigns each HTTP request a server-generated UUID, stores it in HTTP scope state, replaces any caller-supplied `X-Request-ID` response header, and scopes the ID through a `ContextVar`. Error responses and structured request logs use that ID. Lifespan and WebSocket ASGI scopes are delegated unchanged; they do not enter HTTP request logging, metrics, or context mutation.

`api/app/observability/metrics.py` keeps bounded in-process counters (maximum 128 series by default), keyed by allowlisted method, normalized route, and status class, with accumulated duration. This is neither durable nor a multiprocess aggregation mechanism.

`api/app/observability/logging.py` emits compact JSON with only `event`, `request_id`, `method`, `route`, `status`, `status_class`, and `duration_ms`. Methods and routes are normalized/allowlisted; unmatched routes do not expose concrete paths or query strings.

## Errors, authentication, and throttling

`api/app/errors.py` maps declared domain and HTTP failures to constrained public envelopes with stable codes/messages and request IDs. Validation details are bounded to 20 issues and constrained to approved locations and types. Internal exception text is not part of the public error contract. `api/app/observability/request_id.py` converts unhandled HTTP application exceptions to a generic 500 envelope without logging exception contents.

Authentication failures are generic at the route boundary (`api/app/api/admin_auth.py`); credential checks use a dummy hash when staff or credential lookup fails (`api/app/auth/credentials.py`). The tests exercise safe failure behavior, not all production threat scenarios.

The Admin session validator requires its configured signing secret. Each Admin-capable API consumer passes the `SecretStr` value only when both Admin authentication policy and token signing are configured. Mixed Admin/Staff consumers retain their existing Staff fallback when signing is unavailable; Admin-only consumers fail closed with a generic 401. Invalid and revoked Admin bearer tokens remain generic denials. This wiring does not weaken token validation or accept unsigned Admin credentials.

`api/app/main.py` owns an in-process bounded authentication rate limiter. The staff login route hashes the client address before using it as a limiter key, returns generic 429/503 responses, and bounds concurrent password hashing. This local limiter is not shared across workers or hosts. Admin-login and staff-PIN limits are covered by focused existing tests; no hosted load or distributed-limit behavior is claimed.

## CI and policy boundary

The only CI definition inventoried for this slice is `.github/workflows/api.yml`; it describes the API workflow but does not establish hosted execution evidence here. No hosted CI result was inspected or claimed. P1.1, P1.3, and P1.4 remain separate contract boundaries; this document adds only P1.5 local observability evidence and does not claim all of P1 is complete.

Retention duration, access controls, alert ownership, and operational review of logs/metrics remain unresolved product and operations decisions. This contract does not invent values or authorize production logging, monitoring, or retention changes.

## Local evidence

Writer and independent-verifier evidence is tracked in `odd/tasks/p1-5-observability.md`. The pre-repair focused run had 73 passes and 3 failures: the validator now required a signing secret, but ten API consumers still called it with two arguments, turning expected generic 401 responses into 500s. Targeted regression tests first reproduced the bad call shape (10 failures); after the authorized integration repair, the complete focused local set passed 131 tests in 33.35 seconds. It includes HTTP correlation, concurrent context, safe structured-log fields, non-HTTP ASGI pass-through, Admin secret wiring for all ten consumers, Staff fallback with no usable Admin secret, Admin-only fail-closed behavior, and a real signed Admin token followed by invalid and revoked-token generic denials. Coverage is synthetic/local: no `.env`, real credentials, live database, external provider, hosted CI, or production system was used. The focused run emitted one upstream Starlette/httpx deprecation warning; independent verification reproduced 131 passes in 33.40 seconds with the same existing warning and no actionable code issue.
